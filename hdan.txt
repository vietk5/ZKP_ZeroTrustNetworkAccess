--- GIAI ĐOẠN 1: MẠCH VÀ TRUSTED SETUP -----------------------------------------

[1.1] Biên dịch mạch

Invoke-WebRequest -Uri "https://github.com/iden3/circom/releases/download/v2.2.3/circom-windows-amd64.exe" -OutFile circom.exe
Unblock-File .\circom.exe

.\circom.exe --version
    -> Tải trình biên dịch Circom bản gốc cho Windows

.\circom.exe circuits/device_posture.circom --r1cs --wasm --sym -o build -l node_modules
    -> Biên dịch mạch DevicePosture.
	--r1cs: xuất ra hệ phương trình: ds 9986 pt dạng axb=c, dùng cho quá trình trusted setup, qtr này sẽ đọc file này để nbooij suy thánh đá thức.
	--wasm: xuất ra bộ tính witness, nhận input và tính giái trị cho toàn bộ khoảng 10000 dây của mạch. file này được dùng cho thiết bị mỗi lần tạo prooof, trong lib/prover.js, lệnh snarkjs.groth16.fullProve(input, WASM, ZKEY) chạy file .wasm trước để có witness, rồi mới dùng zkey để ghép proof. chính file .wasm này dừng lại khi dữ liệu không thỏa mạch tức là khi có 1 điêu kiện sai.
       Kết quả: 8.279 ràng buộc phi tuyến (), 1.707 tuyến tính (),
                9 public input, 8 private input, 1 output.
       Sinh ra: build\device_posture.r1cs, build\device_posture.sym,
                build\device_posture_js\device_posture.wasm

npx snarkjs r1cs info build/device_posture.r1cs
    -> Xem thống kê mạch: 9.986 ràng buộc

[1.2] Trusted setup – Phase 1 (Powers of Tau)
npx snarkjs powersoftau new bn128 14 build/pot14_ptau -v
    -> Tạo khung Powers of Tau cỡ 2^14 = 16.384 ràng buộc, tạo một khung chứa các lũy thừa của τ dưới dạng điểm trên đường cong BN254

npx snarkjs powersoftau contribute build/pot14_0000.ptau build/pot14_0001.ptau --name="Viet" -e="..."
npx snarkjs powersoftau contribute build/pot14_0001.ptau build/pot14_0002.ptau --name="Duy" -e="..."
    -> Hai lượt đóng góp bí mật (Việt rồi Duy). Lưu ý đúng chuỗi 0000 -> 0001 -> 0002

npx snarkjs powersoftau verify build/pot14_0002.ptau
    -> Kiểm tra chuỗi đóng góp. Kết quả: Contribution #1 Viet, #2 Duy, Powers Of tau file OK!

Measure-Command { npx snarkjs powersoftau prepare phase2 build/pot14_0002.ptau build/pot14_final.ptau | Out-Default }
    -> Chuẩn bị cho phase 2. Mất 71,65 giây. Sinh pot14_final.ptau (~18 MB)

[1.2] Trusted setup – Phase 2 (riêng cho mạch)
Measure-Command { npx snarkjs groth16 setup build/device_posture.r1cs build/pot14_final.ptau build/dp_0000.zkey | Out-Default }
    -> Sinh zkey ban đầu từ mạch. Mất 7,42 giây

npx snarkjs zkey contribute build/dp_0000.zkey build/device_posture.zkey --name="ZTNA-lab" -e="..."
    -> Trộn bí mật mới vào delta

npx snarkjs zkey verify build/device_posture.r1cs build/pot14_final.ptau build/device_posture.zkey
    -> Kiểm tra zkey khớp mạch và ptau. Kết quả: ZKey Ok!

npx snarkjs zkey export verificationkey build/device_posture.zkey build/verification_key.json
    -> Xuất verification key cho PDP (4.574 byte)

dir build
    -> device_posture.zkey 5.291.906 byte | verification_key.json 4.574 byte

  D2 cảm biến nhiệt  fw 210 sec 4 dtype 1   -> không đạt (firmware cũ)

  D4 cảm biến ẩm     fw 210 sec 2 dtype 2   -> không đạt cả hai

  D6 camera          fw 450 sec 4 dtype 3   -> camera
  D7 cảm biến nhiệt  credential hết hạn     -> không đạt

  factory/temperature  fw>=300 sec>=3 loại {1,4}  phiên 300 s
  factory/humidity     fw>=300 sec>=3 loại {2,4}  phiên 300 s
  factory/camera       fw>=400 sec>=4 loại {3}    phiên 120 s
  factory/admin        fw>=500 sec>=5 loại {4}    phiên 60 s

NHẬT KÝ

  logs\pep_events.csv        Sự kiện kết nối, publish, subscribe
  logs\device_<ID>.csv       Thời gian tạo proof của từng thiết bị

================================================================================
PHẦN 5. XỬ LÝ SỰ CỐ THƯỜNG GẶP
================================================================================

Thiết bị đạt chuẩn (D1, D5, D6) bỗng không tạo được proof, lỗi ở dòng 79
  -> Credential hết hạn 24 giờ. Chạy: node issuer/issue.js

"EADDRINUSE: address already in use 127.0.0.1:8081" (hoặc 1883, 8080)
  -> PDP/PEP đang chạy ở terminal khác. Tắt bản cũ (Ctrl+C) hoặc dùng luôn bản đó.

Thiết bị báo PEP_UNREACHABLE
  -> Chưa bật PEP (Terminal 2).

Thiết bị báo CHALLENGE_ERR PDP_UNREACHABLE
  -> Chưa bật PDP (Terminal 1), hoặc bật PEP trước PDP.

D5 mãi PROOF_FAIL ở topic temperature
  -> Chính sách đang để minFw = 400. Chạy:
     node scripts/set_policy.js factory/temperature minFw 300

"Could not write the output in the given path" khi biên dịch mạch
  -> Dùng .\circom.exe thay vì node node_modules/circom2/cli.js

Kết nối MQTT bị treo, không phản hồi
  -> Client gửi password mà thiếu username (chuẩn MQTT 3.1.1 bắt buộc).
     Các script hiện tại đã đặt username "zkp-proof".

Dòng "ERROR: 4 Error in template DevicePosture_251 line: XX"
  -> Không phải lỗi chương trình: đó là thiết bị không đạt chính sách.
     line 70 = firmware | line 74 = mức an toàn | line 79 = hết hạn
     ForceEqualIfEnabled line 56 = chữ ký không khớp (credential không phải của mình)
